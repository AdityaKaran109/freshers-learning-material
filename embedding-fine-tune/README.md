# Fine-tuning an embedding model on drug brand names

Teach a sentence-embedding model that two medicine brands with the **same active
ingredients** belong together — and that two brands whose *names* look alike do
not.

```
Mox 500mg      = Amoxicillin                      \  same molecule,
Novamox 500    = Amoxicillin                      /  should be CLOSE

Ibugesic 400   = Ibuprofen                        \  nearly identical names,
Ibugesic Plus  = Ibuprofen + Paracetamol          /  should be FAR APART
```

That second case is the whole point. An off-the-shelf model scores
`Ibugesic 400` vs `Ibugesic Plus` at **0.97** cosine similarity while scoring
`Brufen 400` vs `Ibugesic 400` — actually the same drug — at only **0.66**. It is
matching spelling, not medicine.

> **This folder contains code only.** No datasets, no model weights, no
> checkpoints, no plots. Everything is downloaded or regenerated by the scripts
> below.

---

## Run order

Run these four in sequence. Each one depends on the previous.

| # | Script | What it does | Produces |
|---|--------|--------------|----------|
| 1 | `model_download.py` | Downloads the base model + dataset | `FremyCompany/`, `shudhanshusingh/` |
| 2 | `prepare_dataset.py` | Turns 254k medicines into training pairs/triplets | `data/*.csv` |
| 3 | `finetune.py` | Fine-tunes the embedding model | `models/drug-embed-v1/` |
| 4 | `test_model.py` | Scores the model and plots the clusters | `*.png` + metrics |

### 0. Setup

```bash
python -m venv venv
source venv/Scripts/activate      # Windows Git Bash;  venv\Scripts\activate on cmd
                                  # source venv/bin/activate on Linux/macOS
pip install -r requirements.txt
```

Install PyTorch to match your CUDA version — see the comment at the top of
`requirements.txt`. `finetune.py` **requires a CUDA GPU** and exits if none is
found.

### 1. Download the model and dataset

```bash
python model_download.py
```

- **Base model:** [`FremyCompany/BioLORD-2023`](https://huggingface.co/FremyCompany/BioLORD-2023),
  a biomedical sentence-embedding model — a better starting point than a
  general-purpose one because it already knows something about drug names.
- **Dataset:** [`shudhanshusingh/az-medicine-dataset-of-india`](https://www.kaggle.com/datasets/shudhanshusingh/az-medicine-dataset-of-india)
  — 253,973 Indian medicines with real `short_composition1` / `short_composition2`
  columns. Kaggle credentials are not required; the download is anonymous.

Both are skipped if already present. Re-running is safe.

> **Why this dataset matters.** An earlier version of this project used a 1mg
> product listing that had *no* composition columns, so ingredients had to be
> guessed from product titles. Every training label was a guess, and the
> resulting accuracy number measured agreement with those guesses. Use a source
> with real composition fields.

### 2. Build the training data

```bash
python prepare_dataset.py \
    --csv "shudhanshusingh/az-medicine-dataset-of-india/A_Z_medicines_dataset_of_India.csv" \
    --out ./data
```

Writes four files to `data/`:

| File | Columns | Used for |
|------|---------|----------|
| `train_pairs.csv` | `text_a, text_b` | positives (MultipleNegativesRankingLoss) |
| `val_pairs.csv` | `text_a, text_b` | held-out positives |
| `train_triplets.csv` | `anchor, positive, hard_negative` | explicit hard negatives |
| `val_triplets.csv` | `anchor, positive, hard_negative` | held-out evaluation |

**Train and validation use disjoint compositions**, so validation brands are
never seen during training.

What the script does, and why each step exists:

- **Canonical composition key.** `"Amoxycillin (500mg)"` and
  `"Amoxicillin  (500 mg)"` both become `amoxicillin`. A brand's identity is the
  unordered *set* of its salts, so `A + B` and `B + A` are one group.
- **Spelling and alias collapsing.** `Amoxycillin → Amoxicillin`,
  `Paracetamol/Acetaminophen → paracetamol`, `Diclofenac Sodium → diclofenac`
  (counter-ions are the same active molecule). Disable with `--keep_salt_forms`.
- **Brand-name cleanup.** `"Augmentin 625 Duo Tablet" → "Augmentin 625 Duo"`.
- **Bare brand recovery.** `"Calpol 500mg" → "Calpol"`, kept only when the root
  maps to exactly one composition — so `Novamox` (amoxicillin) is never merged
  with `Novamox CV` (amoxicillin + clavulanate). This matters because people
  search for `Crocin`, not `Crocin Advance 500mg Tablet`.
- **Truncation guard.** The source stores only two salt columns, so a title
  advertising three strengths (`Diamerth G 750mg/50mg/250mg`) has an incomplete
  composition and would manufacture false positives. Those rows are dropped
  (~6.2k). Keep them with `--keep_truncated`.
- **Coverage sampling.** Groups are huge — 5,883 brands share
  *amoxicillin + clavulanic acid*. Enumerating all pairs is `C(n,2)` and will
  exhaust memory; sampling a flat 20 pairs per group leaves most brands unused.
  Instead each group is shuffled and neighbours paired, so **every brand appears**
  without ever materialising all combinations.
- **Hard negatives.** For each anchor, the negative **shares a salt but has a
  different full composition** — `Mox 500` (amoxicillin) vs `Mox CV 625`
  (amoxicillin + clavulanate). Random negatives teach almost nothing; these are
  the cases the model actually gets wrong.

Useful flags: `--pair_rounds`, `--triplet_frac`, `--val_frac`,
`--drop_discontinued`, `--no_brand_roots`, `--no_comp_anchors`.

### 3. Fine-tune

```bash
python finetune.py \
    --base ./FremyCompany/BioLORD-2023 \
    --data ./data \
    --out ./models/drug-embed-v1 \
    --epochs 3 --batch_size 32 --lr 2e-5
```

Trains with `MultipleNegativesRankingLoss`: every positive pair treats the rest
of the batch as negatives, and the triplet file adds explicit hard negatives on
top. Prints a triplet accuracy before and after training, then saves the best
model to `--out`.

Larger `--batch_size` is genuinely better here — MNRL draws its negatives from
the batch, so a bigger batch means a harder, more informative task.

### 4. Evaluate and plot

```bash
# the fine-tuned model
python test_model.py --model ./models/drug-embed-v1 --title "After fine-tuning" --out after.png

# the untouched base model, for comparison
python test_model.py --model ./FremyCompany/BioLORD-2023 --title "Before fine-tuning" --out before.png
```

Evaluates on 28 real brands across 7 verified compositions and reports:

- **mean cosine, same composition** — should go up
- **mean cosine, different composition** — should go down
- **separation margin** — the difference between the two; **this is the number
  that matters**
- **nearest-neighbour accuracy** — for each brand, does its closest neighbour
  share its composition?
- a **look-alike table** of pairs that are easy to confuse

## Reading the results honestly

Two traps, both of which produced convincing-looking but meaningless results
earlier in this project.

**1. Do not compare PCA plots between two models.** PCA is refit on each set of
embeddings, so the axes are arbitrary. Rotations, flips and shifts between a
"before" and "after" plot mean nothing. Compare the printed metrics instead —
`test_model.py` puts them in the plot title for exactly this reason.

**2. A rising accuracy number can hide a worse model.** Fine-tuning with MNRL
can pull *everything* closer together. Same-composition similarity rises, which
looks like success, but different-composition similarity rises just as much and
the model has actually lost discriminating power. Always look at the **margin**
between them, not the same-composition score alone:

| | base model | fine-tuned on *guessed* labels |
|---|---|---|
| mean cosine, same composition | 0.518 | 0.676 &nbsp;⬆ *looks better* |
| mean cosine, different composition | 0.376 | 0.587 &nbsp;⬆ *rose just as much* |
| **separation margin** | **+0.142** | **+0.089** ⬇ **worse** |
| **nearest-neighbour accuracy** | **0.679** | **0.643** ⬇ **worse** |

Also make sure the labels you are scoring against are correct. `Augmentin` is
amoxicillin **+ clavulanic acid**, and `Combiflam` is ibuprofen **+
paracetamol** — a model that separates them from plain amoxicillin and plain
ibuprofen is being *right*, even though a naive "drug class" label calls it a
failure.

## Known limitations

- `finetune.py` currently carves its evaluation set out of `train_triplets.csv`,
  so it scores compositions the model trained on. `data/val_triplets.csv` holds
  disjoint compositions and is the honest set to evaluate against.
- The source dataset stores at most two salts per medicine, so genuine
  three-ingredient products cannot be represented and are dropped.
- Coverage is Indian brand names (allopathy only). It will not know US or EU
  brands — `Advil`, for instance, is absent.
